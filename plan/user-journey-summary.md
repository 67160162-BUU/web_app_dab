# User Journey ฉบับย่อ — DAB DETECTOR

> สรุปจาก `user-journey.md` และ `dab-detector-plan.md` เอาเฉพาะส่วนที่ใช้เขียน User Story และ Test Case ได้ทันที

**ระบบ:** เว็บเกมตรวจจับท่า Dab ด้วยกล้อง ใช้ Google MediaPipe Pose Landmarker ประมวลผลบนเครื่องผู้ใช้ ให้คะแนนความแม่นยำของท่าใน 20 วินาที แล้วบันทึกขึ้นกระดานจัดอันดับ เป็น web เพื่อความบันเทิงตามกระแสท่ามีม ต่างๆบนโลกอินเตอร์เน็ต โดยมีแพลนจะเพิ่มหลาย game mode และหลายท่า

## 3. Pain Points — ปัญหาที่ทำให้ "ไม่ได้เล่น" หรือ "เล่นแล้วไม่สนุก"

ระบบนี้เป็นเว็บเล่นสนุกตามกระแสมีม Pain Point จึงไม่ใช่ปัญหาชีวิตจริงจัง แต่คือ**จุดที่ทำให้ผู้ใช้ปิดแท็บทิ้ง หรือเล่นรอบเดียวแล้วไม่กลับมาอีก**

| #   | Pain Point                                                | ทำไมถึงเจ็บ                                                                                                          | ระบบต้องแก้ยังไง                                                                                                                        |
| --- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | **กลัวเว็บแอบอัดวิดีโอตัวเอง**                            | การเปิดกล้องให้เว็บแปลกหน้าเป็นการตัดสินใจที่คนลังเลที่สุด ถ้าไม่มั่นใจจะปิดทิ้งทันที                                | แสดงข้อความ "ภาพไม่ถูกบันทึกหรือส่งออกจากเครื่อง" **ก่อน** ที่เบราว์เซอร์จะขออนุญาต + ประมวลผลบนเครื่องจริง (พิสูจน์ได้จากแท็บ Network) |
| P2  | **ไม่รู้ว่าท่า Dab ที่ถูกต้องคือท่าไหน**                  | ท่ามีมผ่านยุคมาแล้ว บางคนจำได้ไม่ชัด พอทำแล้วได้คะแนนต่ำจะหาว่าเกมพัง แทนที่จะขำตัวเอง                               | มี GIF ตัวอย่างท่าที่หน้าแรก + เงาโครงร่างระหว่างเล่น                                                                                   |
| P3  | **กดแล้วไม่มีอะไรเกิดขึ้น**                               | โหลดโมเดล MediaPipe ใช้เวลา 2-5 วินาที ถ้าจอว่างเปล่าผู้ใช้จะคิดว่าเว็บเสียแล้วปิดทิ้ง                               | ทุกสถานะที่ต้องรอมี loading indicator ห้ามจอว่างเกิน 1 วินาที                                                                           |
| P4  | **อยากเล่นเกมตามกระแสเดี๋ยวนั้น แต่ต้องโหลดแอป/สมัครสมาชิก** | เห็นมีมใน TikTok แล้วอยากลองทันที แต่พอเป็นแอปต้องโหลดร้อยกว่า MB + สมัคร + ยืนยัน OTP กว่าจะได้เล่นก็หมดอารมณ์ไปแล้ว | เป็นเว็บ เปิดลิงก์แล้วเล่นได้เลย **ไม่ต้องโหลด ไม่ต้องสมัคร** จากกดลิงก์ถึงเริ่มเล่นไม่เกิน 30 วินาที                                   |
| P5  | **เกมมือถือทั่วไปมีแต่จิ้มจอ เล่นแล้วไม่มีอะไรน่าจดจำ**   | เกมกดจิ้มเล่นจบแล้วก็ลืม ไม่มีอะไรให้ขำกับเพื่อน ความสนุกของมีมอยู่ที่ "ได้ทำท่าจริง" ไม่ใช่กดปุ่ม                    | ใช้**ร่างกายจริงเป็นคอนโทรลเลอร์** ผ่านกล้อง + เห็นโครงกระดูกตัวเองขยับสดๆ บนจอระหว่างเล่น                                              |
| P6  | **เล่นคนเดียวแล้วไม่รู้ว่าคะแนนนี้ดีหรือแย่**             | ตัวเลข 78 คะแนนไม่มีความหมายถ้าไม่มีอะไรให้เทียบ ความสนุกของเกมแนวนี้อยู่ที่การอวดและการท้ากลับ                      | แสดงอันดับทันทีในหน้าผล ("คุณอยู่อันดับที่ 34 จาก 210 คน") ไม่ใช่ให้ไปกดดูกระดานเอง                                                     |
| P7  | **เล่นรอบสองรอบก็เบื่อ ไม่มีเหตุผลให้กลับมาอีก**          | เกมมีมส่วนใหญ่ตายเพราะเล่นได้แค่แบบเดียว พอทำคะแนนสูงสุดของตัวเองได้แล้วก็จบ ไม่มีอะไรใหม่                           | วางระบบให้รองรับ **หลาย game mode และหลายท่ามีม** ตั้งแต่ออกแบบฐานข้อมูล (คอลัมน์ `mode`) + กระดานอันดับแยกตามโหมด                      |
| P8  | **เล่นจบแล้วไม่มีอะไรเอาไปอวดหรือขำกับเพื่อน**            | ถ้าแชร์ได้แค่ตัวเลข เพื่อนในกลุ่มจะไม่รู้สึกอยากลอง วงจรการบอกต่อขาดตรงนี้ — ทั้งที่เป็นช่องทางโตหลักของเกมแนวมีม    | capture **ภาพนิ่งช็อตที่ทำได้ดีที่สุด** แล้วสร้างเป็นการ์ดผลคะแนนสำหรับดาวน์โหลด/แชร์กลับเข้ากลุ่ม                                      |
| P9  | **เพื่อนโกงคะแนน กระดานอันดับไม่น่าเชื่อถือ**             | ถ้าที่ 1 คือคะแนน 100 เต็มที่เห็นชัดว่าโกง คนอื่นจะเลิกเล่นเพราะรู้ว่าแข่งไปก็ไม่มีความหมาย                          | state machine กันค้างท่า + ตรวจการเคลื่อนไหวจริง + backend validate ช่วงค่าที่เป็นไปได้                                                 |

## 4. ขั้นตอนการใช้งาน (Step-by-step)

| #   | หน้าจอ / Touchpoint                       | การกระทำของผู้ใช้                                                                                    | การตอบสนองของระบบ                                                                                                        |
| --- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | `index.html` — หน้าแรก                    | เปิดลิงก์จากไลน์ เห็นชื่อเกม, GIF ตัวอย่างท่า, ปุ่มเดียว "เริ่ม DAB" และข้อความรับรองความเป็นส่วนตัว | แสดง landing page + **เริ่ม preload โมเดล MediaPipe เบื้องหลังทันที** + ดึง Top 5 มาแสดงเรียกความอยากเล่น                |
| 2   | `pages/camera-setup.html` — ขออนุญาตกล้อง | อ่านข้อความ "ภาพจะไม่ถูกบันทึกหรือส่งออกจากเครื่อง" แล้วกดปุ่ม → เบราว์เซอร์เด้งขออนุญาต → กด Allow  | เรียก `getUserMedia()` **หลังผู้ใช้กดปุ่มแล้วเท่านั้น** ไม่ขอตอนโหลดหน้า / แสดง loading ระหว่างโหลดโมเดล                 |
| 3   | `pages/camera-setup.html` — ตั้งท่า       | ยืนถอยหลังให้ตัวเองอยู่ในกรอบเงาบนจอ                                                                 | ตรวจ visibility ของไหล่ 2 ข้าง + สะโพก 2 ข้าง > 0.7 ถ้าครบขึ้น "พร้อม!" อัตโนมัติ พร้อมเก็บ `shoulderWidth` เป็นฐานคำนวณ |
| 4   | `pages/game.html` — นับถอยหลัง            | มองจอ รอ 3-2-1 (มือถือ 5-4-3-2-1)                                                                    | นับถอยหลังพร้อมเสียง แล้วเริ่มจับเวลา 20 วินาที                                                                          |
| 5   | `pages/game.html` — เล่นเกม               | ทำท่า Dab สลับซ้าย-ขวาให้เร็วและถูกต้องที่สุด                                                        | ตรวจทุกเฟรม ~30 fps: คำนวณคะแนน, วาดโครงกระดูกทับภาพและเปลี่ยนสีตามคะแนน, นับจำนวนครั้ง, แสดงเวลาที่เหลือ                |
| 6   | `pages/result.html` — ดูผล                | เห็นคะแนนรวม, คะแนนแยกรายเกณฑ์ 5 ข้อ, ภาพช็อตที่ดีที่สุด และอันดับโดยประมาณ                          | หยุดกล้อง, คำนวณคะแนนสุดท้าย, capture frame ที่คะแนนสูงสุดจาก canvas, เรียก `GET /api/scores/rank/{score}`               |
| 7   | `pages/result.html` — บันทึกคะแนน         | กรอกชื่อเล่น (≤ 12 ตัวอักษร) แล้วกด "ส่งคะแนน" หรือกดข้าม                                            | `POST /api/scores` ส่งเฉพาะ `{nickname, score, dab_count, mode}` **ไม่ส่งภาพ** แล้วคืน `id` มาเก็บใน sessionStorage      |
| 8   | `pages/leaderboard.html` — กระดานอันดับ   | เห็น Top 20 และแถวของตัวเองไฮไลต์ไว้                                                                 | `GET /api/scores/top?limit=20` แล้วเทียบ `id` ใน sessionStorage เพื่อไฮไลต์                                              |
| 9   | `pages/result.html` — เล่นซ้ำ / แชร์      | กด "เล่นอีก" (กลับไปขั้นที่ 4 โดยไม่ขอกล้องใหม่) หรือกด "แชร์"                                       | คงสถานะกล้องและโมเดลไว้ในหน่วยความจำ, สร้างการ์ดภาพผลคะแนนสำหรับดาวน์โหลด/แชร์                                           |

## 5. Edge Cases

| #   | สถานการณ์                                      | ระบบต้องทำอะไร                                                                                                                                      | ลำดับความสำคัญ |
| --- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| E1  | ผู้ใช้กด **Block** ไม่อนุญาตกล้อง              | แสดงหน้าอธิบายว่าเกมจำเป็นต้องใช้กล้อง + วิธีเปิดสิทธิ์ใหม่พร้อมภาพประกอบ + ปุ่ม "ลองใหม่" **ห้ามปล่อยจอขาว**                                       | 🔴 สูง         |
| E2  | เครื่องไม่มีกล้อง / กล้องถูกโปรแกรมอื่นใช้อยู่ | แยก error `NotFoundError` กับ `NotReadableError` แล้วแสดงข้อความต่างกัน + เสนอ "โหมดดูอันดับอย่างเดียว"                                             | 🔴 สูง         |
| E3  | แสงน้อยเกินไป / ยืนไม่เต็มเฟรม                 | ถ้า visibility ของ landmark หลักต่ำกว่าเกณฑ์ติดต่อกันเกิน 1 วินาที แสดง "ขยับให้เห็นตัวมากขึ้น" หรือ "แสงน้อยเกินไป" **ไม่ให้เริ่มเกมจนกว่าจะผ่าน** | 🔴 สูง         |
| E4  | มีคนเดินผ่านหลังจอ / มีคนมากกว่า 1 คนในเฟรม    | ตั้ง `numPoses: 1` ให้ MediaPipe จับคนที่เด่นที่สุด + แสดง "ตรวจพบมากกว่า 1 คน — คะแนนอาจคลาดเคลื่อน"                                               | 🟡 กลาง        |
| E5  | ผู้ใช้ค้างท่า Dab ไว้เฉยๆ เพื่อโกงคะแนน        | state machine: ต้องกลับสู่ท่าปกติ (คะแนน < 40) ก่อนถึงจะนับครั้งถัดไป ค้างไว้จะได้แค่ 1 ครั้ง                                                       | 🟡 กลาง        |
| E6  | ผู้ใช้ถือรูปภาพคนทำท่า Dab มาส่องกล้อง         | ตรวจว่ามีการเคลื่อนไหวจริงระหว่างเฟรม ถ้า landmark นิ่งสนิทเกินไปไม่นับคะแนน                                                                        | 🟢 ต่ำ         |
| E7  | ผู้ใช้สลับแอป / ปิดแท็บกลางเกม                 | ดัก `visibilitychange` แล้ว pause เกม เมื่อกลับมาให้เริ่มรอบใหม่ ไม่นับต่อจากเดิม                                                                   | 🟡 กลาง        |
| E8  | ชื่อเล่นว่างเปล่า / ยาวเกิน / มีคำหยาบ         | ว่าง → ใช้ "Anonymous", จำกัด 12 ตัวอักษร, กรองคำต้องห้าม **ฝั่ง backend ด้วย** (ไม่เชื่อ frontend อย่างเดียว)                                      | 🟡 กลาง        |
| E9  | มีคนยิง API ส่งคะแนนปลอมโดยตรง                 | backend validate `score` 0–100 และ `dab_count` ≤ 40 (ค่าสูงสุดที่เป็นไปได้ใน 20 วินาที) ถ้าเกินตอบ HTTP 422                                         | 🟡 กลาง        |
| E10 | เครื่องช้า เฟรมเรตตก                           | fps < 15 ติดต่อกัน → ลดความละเอียดวิดีโออัตโนมัติ + แสดงคำเตือน                                                                                     | 🟢 ต่ำ         |
| E11 | ยังไม่มีใครส่งคะแนน (leaderboard ว่าง)         | แสดง "ยังไม่มีใครกล้า — เป็นคนแรกเลยไหม?" พร้อมปุ่มเริ่มเกม **ไม่แสดงตารางเปล่า**                                                                   | 🟢 ต่ำ         |
| E12 | GPU delegate ของ MediaPipe พังบนเครื่องผู้ใช้  | try/catch แล้ว retry ด้วย `delegate: "CPU"` ทันที + แสดง "โหมดประหยัด"                                                                              | 🔴 สูง         |
| E13 | ผู้ใช้กดปุ่มส่งคะแนนรัวๆ หลายครั้ง             | ปิดปุ่มทันทีที่กดครั้งแรก + ล้าง state ผลเกมหลังส่งสำเร็จ + rate limit ฝั่ง backend                                                                 | 🟢 ต่ำ         |

## 6. Acceptance Criteria (Checklist)

### 6.1 ด้านการเข้าถึงและความไว้ใจ

- [ ] จากหน้าแรกถึงเริ่มเล่นได้ ใช้เวลาไม่เกิน **30 วินาที** และกดไม่เกิน **3 ครั้ง**
- [ ] ข้อความ "ภาพไม่ถูกบันทึกหรือส่งออกจากเครื่อง" แสดง **ก่อน** ที่เบราว์เซอร์จะขออนุญาตกล้อง
- [ ] `getUserMedia()` ถูกเรียก **หลังผู้ใช้กดปุ่มแล้วเท่านั้น** ไม่ขอทันทีตอนโหลดหน้า
- [ ] ทุกสถานะที่ต้องรอ (โหลดโมเดล, เปิดกล้อง) มีตัวบ่งชี้ ไม่มีจอว่างเปล่าเกิน 1 วินาที
- [ ] เปิดแท็บ Network ตลอดการเล่น 1 รอบ แล้ว **ไม่พบ request ที่ส่งข้อมูลภาพหรือวิดีโอออกจากเบราว์เซอร์**

### 6.2 ด้านการตรวจจับท่าทาง

- [ ] ทำท่า Dab ถูกต้อง ได้คะแนน **มากกว่า 75**
- [ ] ยกแขนขึ้นทั้งสองข้าง / ชูมือเฉยๆ ได้คะแนน **ต่ำกว่า 40** (ไม่ใช่ false positive)
- [ ] ตรวจจับได้ทั้ง **Dab ซ้ายและ Dab ขวา**
- [ ] ยืนใกล้กล้อง (1 ม.) กับยืนไกล (3 ม.) ทำท่าเดียวกัน คะแนนต่างกัน **ไม่เกิน 10 คะแนน**
- [ ] คะแนนบนจอ **ไม่กระพริบไปมา** (ใช้ค่าเฉลี่ยย้อนหลัง 5 เฟรม)
- [ ] ค้างท่า Dab ไว้ 10 วินาที ต้องนับได้ **แค่ 1 ครั้ง**

### 6.3 ด้าน Backend และข้อมูล

- [ ] `POST /api/scores` ที่มี `score = 999` ต้องถูกปฏิเสธด้วย **HTTP 422**
- [ ] `POST /api/scores` ที่มี `dab_count = 100` ต้องถูกปฏิเสธด้วย **HTTP 422**
- [ ] ส่ง `nickname` ว่างเปล่า ต้องบันทึกเป็น **"Anonymous"** ไม่ใช่ error
- [ ] ส่ง `nickname` ยาว 20 ตัวอักษร ต้องถูกตัดหรือปฏิเสธ ไม่บันทึกเกิน 12 ตัว
- [ ] คะแนนที่ส่งขึ้น API ปรากฏใน leaderboard **ทันทีเมื่อ refresh**
- [ ] `GET /api/scores/top` ตอนฐานข้อมูลว่าง ต้องคืน **list ว่าง (200)** ไม่ใช่ error 500
- [ ] ฐานข้อมูล **ไม่มีคอลัมน์ใดที่เก็บภาพหรือข้อมูลชีวมิติ**

### 6.4 ด้าน Edge Case (ต้องสาธิตได้จริง)

- [ ] กด Block ไม่อนุญาตกล้อง → เห็นหน้าอธิบาย + ปุ่มลองใหม่ **ไม่ใช่จอขาว**
- [ ] จำลอง `NotFoundError` และ `NotReadableError` → ข้อความต่างกัน
- [ ] ปิดไฟให้ห้องมืด → ขึ้นคำเตือนและ **ไม่ให้เริ่มเกม**
- [ ] สลับแท็บกลางเกม → เกม pause และเมื่อกลับมาต้องเริ่มรอบใหม่
- [ ] leaderboard ว่าง → เห็นข้อความชวนเล่น ไม่ใช่ตารางเปล่า

### 6.5 ด้านเทคนิคและการส่งงาน

- [ ] `docker compose up` จากเครื่องที่ clone ใหม่ รันได้โดยไม่ error
- [ ] เข้า `http://localhost:8000` เห็นหน้าเว็บ และ `/docs` เห็น Swagger UI
- [ ] URL ที่ deploy มี **HTTPS** และเปิดกล้องได้จริงจากเครื่องคนอื่น
- [ ] ใช้งานได้บนมือถือ (responsive) และหน้าจอ **ไม่เด้ง fullscreen บน iOS Safari**
- [ ] ไม่มี `.env` หรือคีย์ลับใดๆ ใน repository
